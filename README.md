# Лабораторная работа №1. Алгоритмы и структуры данных

## Поиск общего элемента в двух отсортированных массивах

## 1. Постановка задачи

Даны два отсортированных массива целых чисел `a` и `b` длинами `M` и `N`.

Необходимо определить, содержится ли хотя бы один общий элемент в обоих массивах.

Функция возвращает:

- `True`, если существует хотя бы один общий элемент;
- `False`, если общих элементов нет.

Цель лабораторной работы — реализовать четыре алгоритма решения задачи, исследовать их производительность и определить, в каких условиях каждый из них эффективнее.


## 2. Реализованные алгоритмы

Реализованы четыре алгоритма.

| Алгоритм | Временная сложность | Дополнительная память |
|---|---|---|
| Два указателя | O(M + N) | O(1) |
| Бинарный поиск | O(M log N) | O(1) |
| Экспоненциальный поиск | O(M log(2N/M)) | O(1) |
| Двойной бинарный поиск | O(M log(2N/M)) | O(log M) |

M — размер меньшего массива, N — размер большего массива, M ≤ N.

### 2.1. Два указателя

Для каждого массива используется отдельный указатель. На каждой итерации сравниваются текущие элементы:

- если элементы равны, возвращается `True`;
- если элемент первого массива меньше, его указатель сдвигается;
- в противном случае сдвигается указатель второго массива.

Если один из массивов заканчивается, а совпадение не найдено, возвращается `False`.

Сложность: O(M + N) по времени и O(1) по памяти.

### 2.2. Бинарный поиск

Каждый элемент меньшего массива ищется в большем с помощью бинарного поиска.

Если хотя бы один элемент найден, алгоритм возвращает `True`. Если все элементы проверены без совпадений, возвращается `False`.

Сложность: O(M log N) по времени и O(1) по памяти.

### 2.3. Экспоненциальный поиск

Алгоритм напоминает метод двух указателей, однако для продвижения по большему массиву используется экспоненциальный поиск.

Для каждого элемента меньшего массива определяется диапазон, в котором может находиться совпадение. Граница диапазона расширяется экспоненциальными шагами, после чего внутри найденного диапазона выполняется бинарный поиск.

Алгоритм сохраняет текущую позицию в большем массиве и не возвращается к уже пройденным участкам.

Сложность: O(M log(2N/M)) по времени и O(1) по памяти.

### 2.4. Двойной бинарный поиск

Алгоритм использует разделение массивов на части и бинарный поиск позиции разделения.

На каждом этапе определяется положение центрального элемента одного массива в другом. После этого задача рекурсивно рассматривается для соответствующих частей массивов.

Сложность: O(M log(2N/M)) по времени и O(log M) по дополнительной памяти из-за рекурсивных вызовов.

## 4. Методика эксперимента

### 4.1. Генерация данных

Для экспериментов использовались два отсортированных массива без общих элементов.

В первом массиве размещались нечётные числа, во втором — чётные. Значения первого массива равномерно распределялись по диапазону второго массива.

Таким образом, каждый алгоритм должен был выполнить полный поиск, не обнаружив совпадений.

### 4.2. Измерение времени

Для измерения времени использовался `time.perf_counter()`.

Для каждой комбинации размеров массивов выполнялось:
- 5 пакетов измерений;
- 100 запусков алгоритма в каждом пакете;
- вычисление среднего времени одного запуска для каждого пакета;
- выбор медианы пяти полученных средних значений.

Таким образом, каждое итоговое значение в таблице результатов основано на 500 вызовах соответствующего алгоритма.

Медиана используется для уменьшения влияния случайных колебаний времени выполнения и фоновой нагрузки системы.

### 4.3. Объём эксперимента

Всего проведено три серии экспериментов:

| Сценарий | Количество комбинаций |
|---|---:|
| Симметричный рост (M = N) | 9 |
| Фиксированный M = 50 | 9 |
| Изменение отношения N/M | 8 |
| **Всего** | **26** |

Для каждой комбинации проверялись четыре алгоритма.

Итоговый набор содержит 104 значения времени выполнения. Общее количество вызовов алгоритмов — 52 000.


### 4.4. Сценарии исследования

**Сценарий 1. Симметричный рост**

Размеры обоих массивов увеличиваются одновременно, при этом M = N.

Проверяются размеры от 100 до 500 000 элементов.


**Сценарий 2. Фиксированный размер меньшего массива**

Размер меньшего массива остаётся постоянным: M = 50.

Размер второго массива увеличивается от 200 до 2 000 000 элементов.


**Сценарий 3. Изменение отношения размеров**

Размер меньшего массива фиксирован: M = 100.

Размер второго массива изменяется от 100 до 500 000 элементов. Отношение N/M достигает 5000.



## 5. Результаты эксперимента

### 5.1. Симметричный рост размеров массивов

![Симметричный рост размеров массивов](graphs/symmetric_growth.png)

При одинаковых размерах массивов наиболее эффективным оказался алгоритм двух указателей.

При M = N = 500 000 результаты составили:

| Алгоритм | Время выполнения |
|---|---:|
| Два указателя | 0,096295 с |
| Бинарный поиск | 0,825200 с |
| Экспоненциальный поиск | 0,220734 с |
| Двойной бинарный поиск | 0,199356 с |

Два указателя показали лучший результат благодаря линейному проходу по массивам и небольшим накладным расходам.

Обычный бинарный поиск оказался самым медленным из четырёх алгоритмов.

### 5.2. Рост N при фиксированном M = 50

![Рост N при фиксированном M](graphs/fixed_m.png)

При увеличении размера второго массива два указателя постепенно теряют преимущество, поскольку им необходимо последовательно пройти значительную часть обоих массивов.

При M = 50 и N = 2 000 000 получены следующие результаты:

| Алгоритм | Время выполнения |
|---|---:|
| Два указателя | 0,178707 с |
| Бинарный поиск | 0,000097 с |
| Экспоненциальный поиск | 0,000143 с |
| Двойной бинарный поиск | 0,000071 с |

В данном эксперименте двойной бинарный поиск оказался самым быстрым и стабильным. Он выполнил задачу примерно в 2517 раз быстрее алгоритма двух указателей.

### 5.3. Изменение отношения N/M

![Изменение отношения N/M](graphs/ratio_change.png)

При увеличении отношения размеров массивов преимущество постепенно переходит от алгоритма двух указателей к алгоритму, использующему деление диапазонов.

При M = 100 и N = 500 000 (N/M = 5000) результаты следующие:

| Алгоритм | Время выполнения |
|---|---:|
| Два указателя | 0,044619 с |
| Бинарный поиск | 0,000170 с |
| Экспоненциальный поиск | 0,000235 с |
| Двойной бинарный поиск | 0,000121 с |

Двойной бинарный поиск оказался наиболее быстрым.

## 6. Общие выводы


1. **Два указателя** наиболее эффективны при близких размерах массивов. Линейная сложность O(M + N) и небольшие накладные расходы обеспечивают им преимущество в симметричном сценарии.

2. **Бинарный поиск** значительно эффективнее последовательного прохода по большому массиву, когда размеры массивов сильно различаются. Однако выполнение отдельного бинарного поиска для каждого элемента меньшего массива приводит к сложности O(M log N).

3. **Экспоненциальный поиск** с сохранением текущей позиции позволяет не возвращаться к уже пройденным участкам большого массива. Теоретическая сложность составляет O(M log(2N/M)).

4. **Двойной бинарный поиск** показал наилучшее время выполнения в большинстве асимметричных тестов. При этом он использует O(log M) дополнительной памяти из-за рекурсии.

Таким образом, универсального победителя для всех входных данных нет. При близких размерах массивов предпочтительны два указателя, а при существенной разнице размеров двойной бинарный поиск показал наилучшее время выполнения.
